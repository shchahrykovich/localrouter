Hidden dependency this ADR creates: **a Rust program's behaviour now depends on
its own file name.** Copying `localrouter-dev` to `/usr/local/bin/lr` gives a
program with an empty suffix that talks to the release. Resolving links
(`~/.local/bin/localrouter-dev` → the bundle) keeps the normal install correct;
a renamed copy is outside the design (risk R3).

## 9. Invariants

```text
I1. With an empty suffix, every name equals today's name: bundle id, LaunchAgent
    label, program names, data and logs folders, CLI link, note link and import
    line, MCP server name, CA name prefix, default ports 80 and 443.
    enforced by: the "" row of api/instance-names.json, checked by T1 and T9

I2. Two different suffixes never share a data folder, socket, lock, logs folder,
    bundle id, LaunchAgent label, CLI link or note link; an installer replaces
    only a link with its own instance's name.
    enforced by: T1 and T9 (pairwise distinct over all rows), T10

I3. The suffix is read only from the bundle (own file name or Info.plist), never
    from config.json or an environment variable; a bad suffix stops the program
    before it opens any folder.
    enforced by: T1 (rule), T7 (a binary named localrouter-Dev exits with an error)

I4. Every text a person or an agent reads names its own instance's CLI, help URL
    and ports.
    enforced by: T5 (render every text for -dev) and T6 (source scan, grows by itself)

I5. The updater never checks, downloads or installs when the suffix is not empty.
    enforced by: T11

I6. install.sh replaces LocalRouter.app only when called with --suffix "".
    enforced by: the script's own guard; M1 (no shell test tool, see test plan)

I7. publish.sh stops when a suffix is given.
    enforced by: the script's own guard; checked by hand in M6

I8. set_config changes only the fields it was given; every other field keeps the
    value config.json has on disk at that moment.
    enforced by: T4

I9. A suffixed daemon never falls back to ports 80 or 443: the instance defaults
    apply when config.json is missing, when it does not parse, and to each field
    missing from it; an existing file is never rewritten at start.
    enforced by: T3

I10. Uninstall in one instance removes only that instance's folders, links, CA
     and LaunchAgent.
     enforced by: T10 (links, folders in a temp home); M5 (keychain, launchd)

I11. Rust and Swift derive the same names for the same suffix.
     enforced by: T1 and T9 read the same api/instance-names.json

I12. Settings shows the Daemon section with version and ports exactly when a
     bound port is not 80 or 443, or when there is a problem to show.
     enforced by: T12
```

I9 came from reading `store.rs` while writing this manifest: a broken
`config.json` is moved aside and `Config::default()` (80, 443) is used
(`apps/daemon/src/store.rs:53-63`), and `#[serde(default)]` fills a missing
field with 80 or 443 (`libs/core/src/config.rs:8`). Without I9, a dev instance
with a partial file would reach for the release's ports.

## 11. Blast radius

```text
The maintainer's existing ad-hoc LocalRouter.app
  dependency:   an older install.sh built it with release names
  impact:       it runs as "the release", with an ad-hoc signature, and does not update
  failure mode: silent. It looks like the release but never updates itself. The fix is
                one manual install of the GitHub release.

Claude Code sessions with both notes imported
  dependency:   two notes with nearly the same text in one context
  impact:       an agent may pick either CLI
  failure mode: silent. Routes land in the other instance; the user does not see them
                in the app they look at. Answered by the "when to use it" sentence
                in the suffixed note and MCP instructions (gap G1).

Hand edits of config.json
  dependency:   set_config wrote the in-memory config
  impact:       a port edit is undone by the next Settings switch
  failure mode: silent, today. Fixed by I8.

Browser cookies
  dependency:   browsers do not separate cookies by port
  impact:       shop.localhost:443 and shop.localhost:7443 share cookies
  failure mode: visible but confusing: a login in one instance shows up in the other.
                Accepted; the help page says so.

TCP routes
  dependency:   each TCP route has its own listen port on 127.0.0.1 and ::1
  impact:       two instances cannot both use listen port 15432
  failure mode: visible: the second shows "Listen port is taken" (listenFailed).

Scripts and docs that name paths
  dependency:   CLAUDE.md, docs/dictionary.md, help.md name LocalRouter.app, localrouterd, localrouter
  impact:       they stay true for the release; they must mention the suffix
  failure mode: a reader follows release names while running a dev instance

LOCALROUTER_HOME set in a shell
  dependency:   it wins over the suffix for folders
  impact:       localrouter-dev talks to a test folder
  failure mode: visible in `localrouter-dev status` (instance and folder lines, gap G4)
```

**Confirmed unaffected:** the proxy, TCP forwarding, route validation and
lookup, the request log, the socket API version and shapes, the MCP tool list,
`routes.json` format, the updater of the release, DNS and `/etc/hosts`. No root
rights are needed; ADR 01's "no root" rule holds.

## 13. Risks

```text
R1. The shell copy of the names (release-lib.sh) can drift from the Rust and Swift
    copies. instance.json checks Rust and Swift only; there is no shell test tool.
    The build checks the result instead: build-app.sh fails if the bundle does not
    contain localrouterd<S> and localrouter<S>, and M1 checks the rest by hand.

R2. A set_config read-merge-write can still lose a hand edit saved in the few
    milliseconds between its read and its write.

R3. A copy of the CLI under another name has an empty suffix and talks to the
    release. Links are resolved, so the normal install is safe; a copy is not.

R4. Two notes in one Claude Code context: the "when to use it" sentence lowers
    the chance of a wrong pick but cannot remove it. M3 measures it.

R5. 7080 or 7443 may be in use on a user's Mac. The dev daemon then reports a bind
    error and the user edits config.json; nothing else breaks.
```

## Architectural drift

```text
~ Different: the Claude Code note is a template in libs/core/src/note.md, printed
  by the bundled CLI (`<cli> note`), not rendered by sed in build-app.sh.
  status: ACCEPTED
  reason: one implementation fills every text, so the shell copy of the names
          cannot drift from Rust (reduces risk R1). build-app.sh also stops when
          the note's title does not name the instance it builds.

+ Unexpected: build-app.sh writes the note to a temp file and moves it into the
  bundle. Writing from the bundled CLI straight into the new bundle failed with
  "Input/output error" on every run inside build-app.sh, never by hand. Cause
  unknown.
  status: ACCEPTED

+ Unexpected: an ad-hoc app registers its daemon again when it does not answer
  2 s after start, and install.sh removes the old job (bootout) instead of
  restarting it (kickstart). Found by M1: after a reinstall, launchd refused to
  start the rebuilt daemon ("spawn failed", exit 78, "needs LWCR update"). With
  kickstart the re-registration failed one time in three; with bootout it
  worked in 5 of 5 reinstalls. Without --launch, the daemon now starts when the
  app is opened. Release builds are signed by team and are not affected.
  status: ACCEPTED

+ Unexpected: restart_needed compares with the ports the daemon started with.
  T4 showed it was false after a second set_config call although the new port
  was never bound.
  status: ACCEPTED

+ Unexpected: set_config refuses a config.json that does not parse, instead of
  replacing it.
  status: ACCEPTED (a hand edit with a typo is not lost)

+ Unexpected: Step 7 of the help page keeps the release names in a suffixed
  instance, with a sentence that says why: project files are shared with people
  who run the release. The render test (T5) skips Step 7 and the instance note
  on purpose.
  status: ACCEPTED

~ Different: the 103-byte socket limit holds for user names up to 28 characters
  with the longest suffix, not for any length (01 said "keeps the socket path
  under the limit"). A longer path is refused at start, as before.
  status: ACCEPTED (01 corrected)

~ Different: the source scans first looked only for "localrouter ",
  "router.localhost" and "LocalRouter.md". M1 found fixed names they missed
  ("Open LocalRouter.app or run localrouterd.", the daemon's own messages). The
  scans now also look for "localrouterd" and "LocalRouter.app".
  status: ACCEPTED

- Missing: manual tests M2 (trust the dev CA in a browser), M3 (Claude Code with
  both notes), M5 (uninstall the dev instance) and M6 (release smoke test), and
  the UI part of M4 (how the Daemon section looks).
  status: FIX_REQUIRED before the next release
```
