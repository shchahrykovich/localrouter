{{INSTANCE_NOTE}}LocalRouter gives local servers stable names instead of ports.
HTTP dev servers get https://<name>.localhost URLs; the reply of register_route has the exact URL, with the port when it is not the default one.
Databases and other TCP services get <name>.localhost:<listen_port> (one loopback port per route).
Typical flow: call find_free_port, start the dev server on that port, then register_route with a note that says what the route is for. For a git branch or worktree use one label in front of the project: feat-login.shop (labels are a-z, 0-9 and '-'). Set owner_pid to the dev server's process id to remove the route automatically when it exits. Tell the user the URL from the reply.
Several apps of one site can share a name. register_route with path "/blog" sends /blog and /blog/... to that server; the route without a path gets every other path. The app must serve under that path (Next.js basePath, Vite base), or set strip_path for a server that answers at /. basePath, base and assetPrefix also change the production build: ask the user before you change them. `{{CLI}} which <url>` shows which route answers a URL.
To show HTML or other files without a server, register_route with folder (an absolute path) instead of port: the folder's index.html, or a list of its files, is served. Names that start with '.' are not served.
The proxy: get_proxy returns the proxy URL (127.0.0.1:{{PROXY_PORT}} by default), environment variables and Chrome flags, so a program the user wants to watch sends its traffic through LocalRouter; get_logs then shows it. Turn it on with `{{CLI}} proxy on`, start a command with `eval "$({{CLI}} proxy env)" && <command>`, or Chrome with `{{CLI}} proxy chrome`. HTTPS hosts are inspected by default (inspect list `*`; `{{CLI}} proxy inspect rm '*'` makes them tunnels, `{{CLI}} proxy inspect add <host>` inspects one), and an inspected host needs the user to trust the inspection CA (`{{CLI}} proxy trust`; macOS asks for their password). You cannot change the proxy of a program that is already running, and that includes yourself. Never write proxy settings into project files: other people on the project may not have LocalRouter. Proxy clients: `{{CLI}} proxy client add <name>` gives one program a port of its own; get_proxy with client gives its URL and env, and its requests carry _client in the log. A phone cannot use 127.0.0.1 (it is the phone itself): the user sets up a phone in the app (Proxy tab, Set up iPhone); you cannot, and get_proxy never returns its setup URL.
Proxy log: the proxy writes every request it carries to HAR files in {{PROXY_LOG_FOLDER}}; the user sees them at {{PROXY_LOG_URL}}; get_proxy's log block has the folder. Headers are written as they are, cookies and API keys too; request and response bodies are written too (the first 1 MB of each, content.text, base64 when not text), and WebSocket messages in _webSocketMessages. Do not read a whole file, it can be 100 MB: use jq on the newest file (`ls -t "$({{CLI}} proxy log path)"/proxy-*.har | head -1`), and run it again if the current file was in the middle of a write. `{{CLI}} proxy env` also sets SSL_CERT_FILE, REQUESTS_CA_BUNDLE and CURL_CA_BUNDLE, so Python and curl trust inspected hosts. Turning the log on or off is a CLI command the user sees: `{{CLI}} proxy log on|off`.
Scripts: set_script_rule runs a Lua file on a host's HTTP traffic. An intercept script changes or answers requests while the client waits (an intercept rule with response_body stops streaming for that body); a log script gets a copy of each finished exchange and writes files in output_dir (copy text and events by default, on_event for streams, save for images, video, downloads and uploads). Read the reference first: `{{CLI}} rules api` or {{HELP_URL}}/scripts. Test with check_only: true, then set the rule before the job starts, with owner_pid of a process you started, or call remove_script_rule when done; persistent only when the user asks. get_proxy lists the rules with matched, errors and last_error. Scripts see every header as it is, cookies and API keys too. Do not commit captures: keep output_dir out of git, they hold prompts, API replies, cookies and API keys.
